# Interface direction

The interface uses an operations-desk visual language: warm ivory surfaces, near-black text,
deep desaturated teal actions, muted moss applied states and restrained rust conflict states.
It uses dense editorial hierarchy, hairline borders and minimal elevation. It deliberately
avoids purple, gradients, glass effects, oversized KPI cards, generic AI motifs and decorative
charts.

The generated design board is [coordination-engine-ui-reference.png](coordination-engine-ui-reference.png).
It is a composition reference, not implementation evidence: its sample people, dates,
commitments and connection badges are fictional.

## Evaluation carried into code

- Keep a persistent, permission-filtered navigation rail and a compact company/status header.
- Pair schedule timelines with tables and action lists rather than making a chart the product.
- Preserve separate source, interpretation, solver, validation, approval, commit, sync and
  acceptance states.
- Distinguish unchanged, moved, added, protected and restricted work with text and patterns as
  well as colour.
- Prefer lists and tables to grids of rounded cards.
- Keep model-assisted work visually subordinate to human decisions and trusted checks.

## Generation record

The board was generated with the built-in image generation tool using the `ui-mockup` use case.
The prompt requested four production-oriented native desktop screens: manager workspace, plan
review, employee work and connection status. It required accessible text-labelled state,
practical desktop density, solid ivory/ink/teal/rust/moss colours and explicit avoidance of
purple, gradients, glassmorphism, neon, AI orbs, sparkle motifs, decorative charts and generic
AI-SaaS styling.
