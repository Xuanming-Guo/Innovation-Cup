## Verification record

- Source inspection: all 15 manager + 5 employee images opened individually.
- Production components contain no Northstar seed arrays. Isolated browser fixtures exist only in `apps/desktop/src/test/visual-harness.tsx`, which is not imported by the production entry or included in its build.
- Final desktop verification: `npm.cmd run typecheck --workspace @coordination/desktop`, `npm.cmd run lint --workspace @coordination/desktop`, `npm.cmd run test --workspace @coordination/desktop` and `npm.cmd run build --workspace @coordination/desktop` all passed. Vitest: **38 tests / 9 files**. Build: 87 modules; JS 583.96 kB (162.05 kB gzip), CSS 67.94 kB (13.85 kB gzip). Vite reports a non-failing >500 kB chunk-size advisory.
- Visual captures: **19** final Edge headless browser states at 1672×941, zero captured page exceptions or error alerts; [machine-readable manifest](../apps/desktop/src/test/visual-artifacts/manifest.json). Each is watermarked `BROWSER VISUAL TEST · FIXTURE DATA · NOT LIVE`. All 19 renders were inspected, with targeted reinspection after geometry and lifecycle fixes. A browser capture cannot prove native shortcuts, external-window placement, OS microphone permission or installed-app behavior.

## Deliberate visual/content differences

- Canonical actor names and the five Engineering/Design/QA/Marketing/Support teams replace legacy image copy. R1/R2 are goal gates, not a sixth team.
- Additional Plan review, Notifications and Simulation destinations implement the complete agreed navigation, even where early Home images omit them.
- Microsoft provider rows use simple typographic source marks, not copied external application chrome or a claim of live integration.
- Missing, empty, revoked, unconfigured and failed states are truthful. No canned successful reply, fabricated check, recording waveform or completed task is rendered.
- The prior connected plan/employee workflows remain reachable while the newer storyboard components reuse their exact-version API contracts.

## Final comparison findings and remaining evidence

The browser comparison corrected the manager Home composer's vertical placement, employee Home whitespace/consent-card proportions, ALTO vector mark, graph drawer alignment with the page header, deterministic 17-task label spacing, icon-based team hubs, two-line server-provided goal, and graph conversation placement. Opening a graph uses the compact rail unless explicitly overridden. Canonical fixtures name Maya (Software Delivery Director), Alex (Engineering), Iris (Design), Priya (QA), Nora (Marketing), and Sam (Support).

Comparison also caught functional issues: the calendar now adopts scenario time when workspace bootstrap arrives after first render; profile busy/free uses the employee's returned IANA zone; the assistant scrolls its own message list without shifting the whole graph off-screen. Private resource state is discarded synchronously on actor/run/principal changes, with aborted/late replies unable to restore it.

This is not a pixel-difference pass. Real record count, titles, rules, audit labels, role permissions and scenario mode deliberately control rendered content. Additional navigation and scope/audit labels remain visible. OS chrome/external Teams are not imitated. M09's editable capture uses the task owner; a manager without ownership receives the read-only variant. M14 is only the shared browser composer geometry, not a screenshot of an installed overlay over another app. M15 requires an actual configured scanner/transcription provider and native microphone permissions and therefore has no fabricated capture.

Reproduce the fixture captures by starting `npm.cmd run dev --workspace @coordination/desktop`, then running `node apps/desktop/src/test/capture-storyboards.mjs`. The runner launches an isolated temporary Edge profile, replaces the application entry only through local CDP interception, and loads the test harness. It uses `--no-sandbox` only for that local test browser because renderer startup under this execution environment otherwise hangs; never use that flag for normal application browsing. `ALTO_BROWSER` can select another compatible Chromium executable. No Supabase credential or real company content is used by the capture harness.
